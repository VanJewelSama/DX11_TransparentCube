## 1. DX11 初始化（只做一次）

初始化的核心就三件事：**创建设备、创建交换链（含后台缓冲）、创建各类不变的管线状态**。

```cpp
// 伪代码
void InitD3D()
{
    // 1. 设备 + 上下文 + 交换链，一步创建
    DXGI_SWAP_CHAIN_DESC desc = {
        .BufferCount = 2,              // 双缓冲：前台显示 + 后台绘制
        .BufferDesc  = { width, height, DXGI_FORMAT_R8G8B8A8_UNORM },
        .OutputWindow = hwnd,
    };
    D3D11CreateDeviceAndSwapChain(..., &device, &context, &swapChain);

    // 2. 拿到后台缓冲，包成"渲染目标视图"（RTV）
    ID3D11Texture2D* backBuffer;
    swapChain->GetBuffer(0, &backBuffer);
    device->CreateRenderTargetView(backBuffer, &rtv);

    // 3. 深度/模板缓冲（一张同尺寸纹理 + DSV）
    device->CreateTexture2D(&depthDesc, &depthBuffer);
    device->CreateDepthStencilView(depthBuffer, &dsv);

    // 4. 视口：NDC 坐标映射到屏幕哪个矩形
    context->RSSetViewports({0, 0, width, height});
}
```

关键概念：

| 对象 | 职责 |
|---|---|
| `ID3D11Device` | 工厂：负责**创建**一切 GPU 资源（纹理、Buffer、Shader、状态对象） |
| `ID3D11DeviceContext` | 快递员：负责**下发命令**（绑定资源、Draw、Present 前的所有操作） |
| `SwapChain` | 管理前后台缓冲，Present 时交换（Flip），避免画面撕裂 |
| RTV | "把后台缓冲当成可以画上去的颜色画布"的句柄 |
| DSV | 深度缓冲的句柄，深度测试用 |

## 2. 资产加载：网格与贴图

**立方体网格**：立方体不用读文件，直接手填顶点数组。注意通常用 **24 顶点**（每个面 4 个）而不是 8 个，因为同一个角在三个面上法线/UV 不同。

```cpp
struct Vertex {
    float3 position;   // 本地空间坐标
    float3 normal;     // 法线（光照要用）
    float2 uv;         // 纹理坐标
};

Mesh CreateCube() {
    Vertex verts[24] = { /* 6 个面 × 4 顶点 */ };
    uint16 indices[36] = { /* 6 面 × 2 三角形 × 3 */ };

    Mesh m;
    m.vb = device->CreateBuffer(VERTEX_BUFFER, verts);       // 顶点缓冲 VB
    m.ib = device->CreateBuffer(INDEX_BUFFER, indices);      // 索引缓冲 IB
    m.indexCount = 36;
    return m;
}
```

**贴图（TextureA）**：硬盘上的 PNG/JPG/DDS 要先解码成 RGBA 像素数组，再上传 GPU。DX11 时代常用 **WIC**（Windows 自带）或 **DirectXTex / stb_image**：

```cpp
Texture LoadTextureFromFile(path) {
    pixels = WIC_Decode(path);                       // 硬盘 → CPU 内存
    tex2d  = device->CreateTexture2D(pixels);        // CPU 内存 → GPU 显存
    srv    = device->CreateShaderResourceView(tex2d);// 让 PS 能"读"它的视图
    return { srv };
}
```

要点：纹理本身和"怎么读它"是分开的——**SRV 是着色器访问资源的入口**；另外还要创建一个 **SamplerState**（决定过滤方式、寻址方式）。

## 3. 代码结构：场景 / 模型 / 相机 / 材质

用最小的抽象把"数据"和"绘制"分开：

```cpp
struct Material {
    Shader*     vs, ps;
    Texture*    texture;        // CubeA 用；CubeB 可以是 nullptr
    float4      baseColor;      // CubeB 的红色、alpha=0.5 就放这
    float       roughness;      // → 简单模型里换算成高光指数
    float       specularIntensity;
    BlendState* blendState;     // 不透明 / 半透明（AlphaBlend）
};

struct SceneObject {            // 场景里的一个可渲染物体
    Transform transform;        // 位置/旋转/缩放 → World 矩阵
    Mesh*     mesh;
    Material* material;
};

struct Camera {
    float3 position, target, up;
    float  fov, aspect, nearZ, farZ;
    Matrix GetViewMatrix();     // LookAt
    Matrix GetProjMatrix();     // Perspective
};

struct Scene {
    vector<SceneObject> objects;
    Camera camera;
    // 简单光照：一个平行光方向 + 颜色
};
```

设计原则一句话：**SceneObject 只存"我在哪、我长什么样"，怎么画交给 Renderer**。
这正是 UE 里 `UWorld/AActor`（逻辑层）和 `FScene`（渲染层）分离的朴素版。

## 4. 每帧 Tick 做什么

```cpp
void Frame()
{
    // ---- ① 逻辑更新（游戏线程干的事） ----
    float dt = timer.GetDeltaTime();
    input.UpdateCamera(scene.camera, dt);        // WASD 移动相机
    for (auto& obj : scene.objects)
        obj.Update(dt);                          // 物体动画/移动（如果有）

    // ---- ② 渲染准备：收集 + 排序 ----
    auto& cam = scene.camera;
    Matrix view = cam.GetViewMatrix();
    Matrix proj = cam.GetProjMatrix();

    vector<SceneObject*> opaqueList, transparentList;
    for (auto& obj : scene.objects) {
        if (obj.material->IsTransparent()) transparentList.push_back(&obj);
        else                               opaqueList.push_back(&obj);
    }
    // 不透明：顺序无所谓（深度测试兜底），可按材质排序减少状态切换
    // 半透明：必须按"离相机从远到近"排序（画家算法）
    sort(transparentList, by DistanceToCamera(cam) descending);

    // ---- ③ 绘制 ----
    renderer.BeginFrame();                        // 清屏、绑 RT
    for (auto* obj : opaqueList)      renderer.Draw(obj, view, proj);
    for (auto* obj : transparentList) renderer.Draw(obj, view, proj);

    // ---- ④ 呈现 ----
    swapChain->Present(1, 0);                     // 垂直同步 + 前后缓冲交换
}
```

**本场景恰好命中半透明渲染的经典规则**：

- CubeA 不透明 → 进 `opaqueList`，先画，**写深度**；
- CubeB 半透明 → 进 `transparentList`，后画，**读深度但不写深度**，按远→近混合；
- 因为 B 在 A 前面，画 B 时它的像素会通过深度测试（比 A 更近），然后
  `最终颜色 = B的红色×0.5 + A已画好的颜色×0.5`，得到"透过 B 看到 A"的效果。
- 如果顺序反了（先画 B 再画 A），A 写入的像素会直接把 B 覆盖掉，透明效果消失——
  这就是半透明必须排在不透明之后的原因。

## 5. 一次 DrawCall 的前后要做什么

`DrawIndexed` 本身只是一条命令，真正的工作量在**绑定正确的管线状态**：

```cpp
void Renderer::Draw(SceneObject* obj, Matrix view, Matrix proj)
{
    // ===== 物体级数据更新 =====
    cbuffer.world     = obj->transform.ToMatrix();
    cbuffer.viewProj  = view * proj;
    cbuffer.lightDir  = scene.lightDir;
    cbuffer.matParams = { obj->material->baseColor,
                          obj->material->roughness, ... };
    context->UpdateSubresource(constantBuffer, &cbuffer);  // CPU → GPU

    // ===== 绑定管线状态（Draw 之前） =====
    context->IASetInputLayout(layout);            // 顶点结构解释器
    context->IASetVertexBuffers(obj->mesh->vb);
    context->IASetIndexBuffer(obj->mesh->ib);
    context->IASetPrimitiveTopology(TRIANGLELIST);

    context->VSSetShader(mat->vs);
    context->VSSetConstantBuffers(constantBuffer);

    context->PSSetShader(mat->ps);
    context->PSSetConstantBuffers(constantBuffer);
    context->PSSetShaderResources(mat->texture->srv);  // 贴图
    context->PSSetSamplers(sampler);

    context->OMSetBlendState(mat->blendState);    // ★ A: 关闭混合; B: SrcAlpha/InvSrcAlpha
    context->OMSetDepthStencilState(...);         // ★ A: 写深度;   B: 只读深度
    context->RSSetState(rasterState);             // 背面剔除、填充模式

    // ===== 发起 DrawCall =====
    context->DrawIndexed(obj->mesh->indexCount, 0, 0);
}

void Renderer::BeginFrame()   // 每帧开头做一次
{
    context->ClearRenderTargetView(rtv, 背景色);   // 清颜色
    context->ClearDepthStencilView(dsv, 1.0f);     // 清深度（1.0 = 最远）
    context->OMSetRenderTargets(rtv, dsv);         // 指定画到哪
}
```

一句话总结：**Draw 之前是"摆好流水线上所有开关和原料"，Draw 之后（帧末）是解绑 + Present**。
CPU 侧到此为止，接下来全是 GPU 的事。

## 6. GPU 渲染流水线（基础四段）

```
顶点数据(VB/IB)
   │
   ▼
┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│ Input       │ → │ Vertex      │ → │ Rasterizer  │ → │ Pixel       │ → Output Merger → 后台缓冲
│ Assembler   │   │ Shader      │   │ (固定功能)  │   │ Shader      │   (固定功能)
└─────────────┘   └─────────────┘   └─────────────┘   └─────────────┘
 组装三角形        逐顶点：           裁剪+透视除法+      逐像素：          深度/模板测试
 从缓冲取顶点      本地→世界→视锥     视口变换+三角形     光照+贴图采样     + Alpha混合
                  →裁剪空间(MVP)     光栅化+属性插值    输出颜色
```

各阶段要点：

1. **IA**：按索引缓冲从 VB 里取顶点，拼成三角形。
2. **VS（可编程）**：每个顶点执行一次。核心工作就是乘 MVP 矩阵：
   `pos_clip = P * V * W * pos_local`。同时把法线、UV、世界坐标传给后面。
3. **光栅化（固定）**：裁剪掉视锥外的部分 → 透视除法到 NDC → 映射到屏幕像素 →
   三角形内部每个像素**插值**出 UV、法线、世界坐标。背面三角形在此被剔除。
4. **PS（可编程）**：每个像素执行一次。用最简单的光照模型即可：

```hlsl
// Lambert 漫反射 + Blinn-Phong 高光
float3 N = normalize(input.normal);
float3 L = -lightDir;
float  diff  = saturate(dot(N, L));
float3 H     = normalize(L + viewDir);
float  spec  = pow(saturate(dot(N, H)), shininess) * specIntensity;
// "粗糙度"在最简模型里换算成 shininess：越粗糙 shininess 越小，高光越散

float4 albedo = texture.Sample(sampler, input.uv) * baseColor;  // CubeA 采样贴图，CubeB 只有红色
float3 color  = albedo.rgb * (ambient + diff * lightColor) + spec;
return float4(color, albedo.a);   // CubeB 的 alpha=0.5 在这里输出
```

5. **OM（固定）**：拿着 PS 输出的像素做三件事——**模板测试 → 深度测试（通过了才更新颜色/深度）
   → Alpha 混合**（`final = src×srcAlpha + dst×(1-srcAlpha)`）。
   CubeB 的透明效果就靠这一步的混合完成。

最终所有像素写进**后台缓冲**，`Present` 把它和前台缓冲交换，屏幕显示出这一帧。

## 7. 对照 UE 的设计思路

UE 的本质结构和上面这套一模一样，只是每层都加了解耦和并行：

| 本 Demo 的小程序 | UE 对应物 |
|---|---|
| SceneObject / Scene | 游戏线程 `AActor / UWorld` → 渲染线程镜像 `FPrimitiveSceneProxy / FScene` |
| Camera 的 view/proj | `FSceneView` / `FViewInfo` |
| opaqueList / transparentList 两个队列 | Pass 系统：**BasePass**（不透明）→ **Translucency Pass**（半透明，按 SortKey=距离从远到近排序）——规则完全相同 |
| Material（shader+状态+参数） | `FMaterialRenderProxy` + PSO（Pipeline State Object，把 VS/PS/混合/深度状态打包缓存，避免重复设置） |
| 每帧收集+排序+逐物体 Draw | `FSceneRenderer::Render`：可见性剔除（视锥/遮挡）→ 收集 MeshBatch → 按 Pass 排序 → 生成 RHI 命令 |
| 直接调 D3D11 API | **RHI 抽象层**：上层只发"RHIDrawIndexed"，底层翻译成 D3D11/D3D12/Vulkan |
| Present | `FRHICmdList` 末尾的 Present，由 SwapChain 提交 |

UE 比 Demo 多的三件事，理解动机即可：

1. **游戏线程 / 渲染线程分离**：逻辑 Tick 和渲染提交并行，所以场景数据要复制一份快照
   （SceneProxy）给渲染线程；
2. **可见性剔除**：画之前先用视锥剔除掉看不见的物体，小场景可以先不做；
3. **状态缓存/PSO**：GPU 状态切换很贵，所以按材质排序、把状态打包，而不是每个物体全量
   重设——只有两个物体时感受不深，但概念是同一个。

## 8. 复习路径建议

按这个顺序动手，每一步都能看到可视化成果：

1. 初始化 + 清屏出纯色背景（验证 SwapChain/RTV 链路）
2. 画一个纯色立方体（VB/IB/VS/光栅化打通）
3. 加相机移动（理解 View/Proj）
4. 加 Lambert 光照（PS 入门）
5. 贴图 + UV（SRV/Sampler）
6. 最后加半透明 CubeB（混合状态 + 排序规则）——最容易踩坑也最能加深理解的一步
